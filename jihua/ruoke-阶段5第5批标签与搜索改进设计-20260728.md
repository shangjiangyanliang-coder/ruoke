# 若可 Ruoke 阶段5第5批：标签与搜索改进设计

> 日期：2026-07-28  
> 状态：已完成交互讨论，待用户审阅书面设计  
> 分支：`feature/notes-mvp`  
> 约束：不修复 F1.1.11、F1.1.12、F1.1.15；未经用户确认不 push

## 1. 背景与目标

第5批原实现采用“先在标签管理页创建标签，再到编辑器选择标签”的交互，并让搜索 ViewModel 长期保留上一次搜索条件。用户确认需要调整为：

1. 在笔记编辑器中直接输入任意标签名称；
2. 已有同名标签直接复用，不存在时自动创建并绑定；
3. 主界面标签页由标签管理改为标签搜索；
4. 标签搜索和标题/正文搜索均支持“部分匹配 / 完全匹配”；
5. 标签搜索支持多标签并集；
6. 两类搜索均支持全部范围、指定书/章/节子树、指定书/章/节层级；
7. 搜索页退出后销毁会话，重新进入时所有条件恢复默认。

本次采用方案 A：保留“标签搜索”和“通用笔记搜索”两个入口，复用统一的笔记查询模型、科目范围模型和 Repository 查询能力。

## 3. 页面与交互设计

### 3.1 编辑器标签输入

- 标签区提供“输入标签，按回车添加”的输入框；
- 输入时按部分匹配展示已有标签建议；
- 点击建议时复用已有标签；
- 按回车或点击添加时：
  - 标签名先执行 `trim()`；
  - 空名称不提交，并显示“标签名称不能为空”；
  - 已有完全同名标签时复用；
  - 不存在时创建标签；
  - 当前笔记已有关联时不重复添加；
- 标签以可删除 Chip 展示；
- 支持连续添加多个标签；
- 标签名称沿用现有数据库唯一规则，英文大小写仍视为不同名称。

已有笔记新增或移除标签时立即落库。新笔记尚无真实 `noteId` 时，标签先作为待保存 Chip 保存在当前编辑会话中：

1. 输入标签不触发自动创建笔记；
2. 用户正常保存笔记后，再创建或复用标签并建立关联；
3. 标题和正文均为空时，不创建笔记、标签或关联；
4. 切换编辑会话时清空待保存标签，不能泄漏到下一条笔记。

### 3.2 标签搜索页

主界面标签入口改为“标签搜索”，不再承担标签新建、改名和删除。

- 输入标签名称；
- 默认采用部分匹配，可切换完全匹配；
- 部分匹配：标签名称包含输入文字；
- 完全匹配：标签名称与去除首尾空白后的输入完整相等；
- 用户可从匹配结果中选择多个标签；
- 笔记结果按已选标签并集计算；
- 未选择标签时显示引导态，不直接列出全部笔记；
- 支持科目范围和三种排序；
- 打开笔记并返回后按当前页面条件刷新。

### 3.3 通用笔记搜索页

- 搜索字段为 `note.title` 和 `note.plain_text`；
- 默认采用部分匹配，可切换完全匹配；
- 部分匹配：标题或正文包含关键词；
- 完全匹配：去除字段和关键词首尾空白后，标题或正文完整等于关键词；
- 可叠加多个标签，标签之间为并集；
- 关键词、标签和科目范围之间为交集；
- 保留最近更新、最早更新和标题升序；
- 没有关键词但选择了标签或特定范围时，仍可执行筛选；
- 空关键词、无标签且范围为全部时，可以显示全部未软删除笔记。

### 3.4 科目范围

两个搜索页面复用同一个单选范围组件，默认“全部笔记”。

| 范围 | 查询规则 |
|---|---|
| 全部笔记 | 包含书、章、节和未分类笔记 |
| 指定书 | 该书自身及其全部章、节的笔记 |
| 指定章 | 该章自身及其全部节的笔记 |
| 指定节 | 仅该节的笔记 |
| 全部书 | 仅直接挂在所有书节点上的笔记 |
| 全部章 | 仅直接挂在所有章节点上的笔记 |
| 全部节 | 仅直接挂在所有节节点上的笔记 |

指定节点使用现有书—章—节树进行单选。指定层级不选择具体节点，只按 `subject.level` 过滤直接归属笔记。未分类笔记仅在“全部笔记”中出现。

### 3.5 页面重新进入

标签搜索页和通用搜索页均使用页面会话状态。退出页面后销毁会话；重新进入时统一恢复：

- 空关键词；
- 无已选标签；
- 部分匹配；
- 全部笔记；
- 最近更新。

## 4. 数据与接口设计

### 4.1 匹配模式

新增共享枚举：

```text
SearchMatchMode.contains
SearchMatchMode.exact
```

标签名称查询和笔记关键词查询均使用该枚举，但分别由各自页面控制。

### 4.2 科目范围模型

新增共享值对象：

```text
SubjectScope.all
SubjectScope.subtree(subjectId)
SubjectScope.level(0 | 1 | 2)
```

`subtree` 根据目标节点层级解析允许的 `subjectId`：

- 书：书、直接章、章下全部节；
- 章：章、章下全部节；
- 节：节本身。

当前数据量较小，Repository 可读取未软删除科目节点后在内存中计算 ID 集合，再交给 DAO 使用 `IN` 条件查询；本批不引入递归 CTE。

### 4.3 笔记查询模型

扩展 `NoteSearchQuery`：

```text
NoteSearchQuery
├─ keyword
├─ keywordMatchMode
├─ tagIds
├─ subjectScope
└─ sortOrder
```

DAO 查询组合为：

```text
未软删除
AND 关键词条件（存在时）
AND 科目范围条件（非 all 时）
AND 标签并集条件（存在时）
```

标签关联继续使用子查询，避免同一笔记因多个标签产生重复结果。

### 4.4 标签查询与绑定

`TagRepository` 增加：

```text
searchTags(keyword, matchMode)
findOrCreateAndAttachTag(noteId, tagName)
attachTagsByNames(noteId, names)
```

`findOrCreateAndAttachTag` 在事务中：

1. 修剪并校验名称；
2. 查找完全同名标签；
3. 不存在时创建；
4. 以防重复方式写入 `note_tag`；
5. 返回最终标签对象。

`attachTagsByNames` 用于新笔记保存后的待保存标签批量处理。笔记创建和标签绑定是两个明确步骤：若正文保存成功但标签绑定失败，笔记保留，待保存标签保留在编辑器中供用户重试。

## 5. 状态管理设计

### 5.1 搜索会话

标签搜索和通用搜索分别使用独立、自动释放的 Provider 会话。不得继续从全局单例恢复上一次查询。

标签搜索状态：

```text
标签关键词、标签匹配模式、匹配标签、已选标签 IDs、
科目范围、排序方式、笔记结果
```

通用搜索状态：

```text
笔记关键词、关键词匹配模式、已选标签 IDs、
科目范围、排序方式、笔记结果
```

两者共用 `NoteRepository.search()`，但互不共享页面条件。

### 5.2 异步一致性

- ViewModel 使用请求修订号；
- 较慢的旧查询不能覆盖较新的条件；
- 标签建议输入使用短防抖；
- 点击搜索按钮或键盘搜索键立即查询；
- 页面销毁后的异步结果不能写入新页面会话。

### 5.3 编辑器状态

- 已有笔记：数据库标签列表是唯一真相源；
- 新笔记：当前编辑会话维护待保存标签名称；
- 标签操作使用会话代次和保存门禁；
- 保存标签期间禁止重复标签提交，但不锁定正文编辑；
- 编辑器路由切换时销毁旧标签输入和待保存状态。

## 6. 错误处理

### 6.1 标签

- 空名称：输入框内提示，不调用 Repository；
- 同名标签：复用，不作为冲突报错；
- 重复关联：保持一条关联，不报错；
- 自动补全失败：保留输入，显示轻量错误并允许重试；
- 添加失败：保留输入或待保存 Chip；
- 移除失败：恢复 Chip，保持界面与数据库一致。

### 6.2 新笔记

- 空笔记：不创建笔记、标签或关联；
- 笔记保存失败：不处理待保存标签；
- 笔记成功但标签失败：显示“笔记已保存，但标签保存失败”，保留待保存标签并允许重试；
- 重试时复用已有笔记和标签，不产生重复记录。

### 6.3 搜索

- 查询失败：保留条件，显示错误态和重试入口；
- 无匹配：显示正常空态；
- 所选节点已不存在：提示“所选范围已不存在，请重新选择”，不得静默扩大到全部范围；
- 软删除笔记和软删除科目不进入结果。
