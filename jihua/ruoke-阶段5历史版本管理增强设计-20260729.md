# 阶段5历史版本管理增强设计

## 1. 目标

在现有完整历史快照基础上增强版本管理：

1. 支持给单个历史版本设置或清除自定义名称；
2. 支持管理模式、多选、全选和批量删除；
3. 恢复历史版本时由用户选择是否保存当前完整状态；
4. 默认直接恢复，不保存当前状态；
5. 保持旧历史版本、旧数据库和现有标题/正文/标签完整快照兼容。

成功标准：

- 未命名版本显示“版本 N”；
- 重命名后只显示自定义名称，不显示版本号副标题；
- 名称清空后恢复显示“版本 N”；
- 同一笔记内自定义名称不重复，名称最长50个字符；
- 删除版本后不重新编号；
- 批量删除要么全部成功，要么全部失败；
- 恢复默认不生成当前状态快照；
- 用户勾选后，恢复前保存当前完整状态；
- 标题、正文、标签和重点恢复仍保持事务原子性。

## 2. 当前结构

当前 `note_version` 表字段：

- `id`
- `note_id`
- `version_no`
- `snapshot_json`
- `created_at`

当前版本页仅支持：

- 按版本号倒序查看；
- 显示“版本 N”和创建时间；
- 点击“恢复”；
- 恢复前固定保存当前完整状态。

当前缺口：

- 表中没有版本名称；
- DAO 没有重命名和批量删除；
- Repository 恢复接口无法表达是否保留当前状态；
- ViewModel 只支持列表和固定策略恢复；
- 页面没有管理模式和多选状态。

## 3. 已确认的产品规则

### 3.1 版本名称

- 自定义名称可选；
- 未设置名称时显示“版本 N”；
- 设置名称后只显示自定义名称；
- 创建时间继续显示为副标题；
- 清空名称表示删除自定义名称，恢复默认显示；
- 保存前去除首尾空格；
- 最长50个字符；
- 同一笔记内不允许重名；
- 不同笔记之间允许同名；
- 重名比较沿用项目现有字符串规则，区分英文大小写；
- 名称不影响版本号、排序、恢复目标和快照内容。

### 3.2 批量删除

- 顶栏“管理”进入选择模式；
- 选择模式显示复选框；
- 支持全选、取消和“删除所选（N）”；
- 删除前显示永久删除二次确认；
- 未选择时删除按钮禁用；
- 删除后不重新编号；
- 允许删除全部版本；
- 不存在的版本 ID 按幂等删除处理；
- 任何属于其他笔记的版本 ID 都使整个操作失败；
- 操作失败时保留选择状态，方便用户重试。

### 3.3 恢复策略

- 恢复确认弹窗显示复选框：
  - “恢复前将当前内容保存为新版本”；
- 默认不勾选；
- 未勾选时直接恢复，不保存当前状态；
- 勾选时先保存当前完整状态，再恢复目标版本；
- 当前状态和目标版本完全一致时不生成重复快照；
- 恢复成功后返回编辑器并刷新；
- 恢复失败时停留在版本页，当前笔记不发生部分更新。

## 4. 方案比较

### 方案 A：在 `note_version` 增加可空名称字段

- 新增 `name TEXT NULL`；
- 版本名称和快照分别存储；
- DAO 直接查询、校验和更新；
- 需要数据库 schema 升级。

### 方案 B：新增版本元数据表

- 使用独立表保存版本名称；
- 不修改原表；
- 需要额外关联、同步删除和错误处理。

### 方案 C：名称写入 `snapshot_json`

- 不修改数据库表；
- 重命名需要重写快照 JSON；
- 名称与正文快照耦合，旧格式兼容复杂。

### 最终选择

采用方案 A。

选择原因：

- 数据职责清楚；
- 重命名无需重写正文快照；
- 查询和约束实现简单；
- 对旧数据只需增加可空列；
- 不引入新表和额外关联；
- 符合当前 Drift 架构。

## 5. 数据库设计

### 5.1 表结构

`note_version` 新增：

```text
name TEXT NULL
```

字段语义：

- `null`：没有自定义名称，界面显示“版本 N”；
- 非 null：已规范化的自定义名称。

不修改：

- `id` 主键；
- `version_no` 递增规则；
- `snapshot_json` 格式；
- 创建时间；
- 列表排序。

### 5.2 数据库迁移

- `AppDatabase.schemaVersion` 增加1；
- 升级回调执行 `ALTER TABLE note_version ADD COLUMN name TEXT NULL`；
- 旧记录自动得到 null；
- 不重写旧 `snapshot_json`；
- 不重新生成版本号；
- 不删除任何旧版本。

### 5.3 唯一性

不新增数据库唯一索引。

原因：

- `name` 可空；
- 只要求同一笔记内自定义名称唯一；
- 现有数据需要平滑迁移；
- Repository 可在事务内查询并校验；
- 可返回现有 `ValidationException` 用户提示。

重命名事务步骤：

1. 按版本 ID 读取目标；
2. 校验目标属于指定笔记；
3. 规范化输入；
4. 空字符串转为 null；
5. 非空名称检查长度；
6. 非空名称检查同一 noteId 下其他版本是否同名；
7. 更新名称。

## 6. 领域模型与接口

### 6.1 `NoteVersion`

增加：

```dart
final String? name;
```

增加显示属性：

```dart
String get displayName =>
    name == null || name!.isEmpty ? '版本 $versionNo' : name!;
```

界面只依赖 `displayName`，避免重复拼接规则。

### 6.2 Repository 接口

新增：

```dart
Future<Result<void>> renameVersion({
  required String noteId,
  required String versionId,
  required String? name,
});
```

语义：

- `name == null` 或 trim 后为空：清除名称；
- 非空：保存 trim 后名称；
- 同笔记重名返回 `ValidationException('版本名称已存在')`；
- 超长返回 `ValidationException('版本名称不能超过50个字符')`。

新增：

```dart
Future<Result<void>> deleteVersions({
  required String noteId,
  required Set<String> versionIds,
});
```

语义：

- 空集合直接成功；
- 重复 ID 由 Set 去重；
- 不存在的 ID 视为已删除；
- 查询到属于其他笔记的 ID 时整体失败；
- 删除后版本号不重排。

修改：

```dart
Future<Result<void>> restoreVersion({
  required String noteId,
  required int versionNo,
  bool saveCurrentBeforeRestore = false,
});
```

兼容性：

- 新参数有默认值；
- 现有调用方即使未同步修改，也自动使用新默认行为；
- 新页面必须显式传递复选框状态，避免依赖隐含默认。

## 7. DAO 设计

`NoteVersionDao` 新增：

```dart
Future<NoteVersionEntity?> getById(String id);

Future<NoteVersionEntity?> getByName({
  required String noteId,
  required String name,
  String? excludingVersionId,
});

Future<int> renameVersion(String id, String? name);

Future<List<NoteVersionEntity>> listByIds(Set<String> ids);

Future<int> deleteByIds(Set<String> ids);
```

DAO 只做类型安全查询和写入，不生成用户提示。

Repository 负责：

- 所属笔记校验；
- 输入规范化；
- 重名判断；
- 事务；
- AppException 翻译。

## 8. 恢复数据流

### 8.1 默认直接恢复

```text
用户选择版本
  -> 恢复弹窗默认不勾选
  -> restoreVersion(saveCurrentBeforeRestore: false)
  -> 读取当前笔记、当前标签、目标版本
  -> 解析并校验目标快照
  -> 不保存当前快照
  -> 原子恢复标题、正文、重点、标签
  -> 返回编辑器刷新
```

### 8.2 保存当前后恢复

```text
用户勾选保存当前
  -> restoreVersion(saveCurrentBeforeRestore: true)
  -> 读取当前完整状态和目标快照
  -> 完整状态不同时保存当前快照
  -> 原子恢复目标状态
  -> 返回编辑器刷新
```

### 8.3 相同状态

无论复选框是否勾选：

- 当前完整状态与目标完整状态相同时不新增版本；
- 恢复可直接视为成功；
- 不重建无变化数据。

## 10. ViewModel 状态与操作

现有 `AsyncNotifier<List<NoteVersion>>` 无法完整表达管理选择和单项操作状态。

改为：

```dart
class NoteVersionState {
  final List<NoteVersion> versions;
  final bool managing;
  final Set<String> selectedIds;
  final bool mutating;
  final AppException? operationError;
}
```

操作：

```dart
enterManagement();
exitManagement();
toggleSelected(String versionId);
toggleSelectAll();
rename({required String versionId, required String? name});
deleteSelected();
restore({
  required int versionNo,
  required bool saveCurrentBeforeRestore,
});
refresh();
```

状态规则：

- 列表刷新后移除已不存在的 selectedIds；
- 删除成功后退出管理模式；
- 删除失败保留 managing 和 selectedIds；
- mutating 时禁用重复重命名、删除和恢复；
- 恢复成功与随后列表刷新结果继续分离；
- 页面离开时 family autoDispose 销毁选择状态。

## 11. 错误处理

| 场景 | 处理 |
|---|---|
| 版本不存在 | “历史版本已不存在，请刷新后重试” |
| 重名 | “版本名称已存在” |
| 名称超过50字符 | “版本名称不能超过50个字符” |
| 跨笔记批量删除 | 整体失败，不删除任何版本 |
| 删除包含不存在 ID | 幂等忽略不存在 ID |
| 删除全部版本 | 成功，页面显示空态 |
| 目标版本已删除 | 恢复失败，当前笔记不变 |
| 快照损坏 | 恢复失败，当前笔记不变 |
| 恢复任一步失败 | Drift 事务整体回滚 |
| 列表刷新失败 | 显示可重试错误，不把已完成数据操作误报为失败 |

## 15. 边界

### 始终执行

- 修改数据库前编写迁移测试；
- 批量删除使用事务；
- 版本号保持稳定；
- 恢复完整状态保持事务原子性；
- 保存和删除失败保留可恢复的 UI 状态；
- 运行定向和全量验证。

### 需要用户确认

- 删除备份；
- push；
- 真机数据清理；
- 改变已确认的默认恢复策略；
- 扩展到版本导出、版本备注或版本自动清理。

### 本批不做

- 版本号重排；
- 版本导出或分享；
- 自动清理旧版本；
- 版本内容预览或差异对比；
- 多笔记之间移动版本；
- 回收站；
- 云端同步。

## 16. 风险与缓解

### 数据库迁移风险

- 风险：旧数据库升级失败；
- 缓解：独立迁移测试、仅新增可空列、不改写旧数据。

### 误删除风险

- 风险：多选误操作；
- 缓解：管理模式、数量显示、永久删除二次确认。

### 默认直接恢复风险

- 风险：用户未勾选时丢失当前状态；
- 缓解：复选框文案明确、恢复确认弹窗明确说明当前内容会被覆盖。

### 重名竞态

- 风险：两个操作同时设置相同名称；
- 缓解：Repository 在事务内查询并更新；当前为单机本地应用，不引入额外数据库索引。

### 接口 fake 扩散

- 风险：`NoteRepository` 新方法影响大量测试 fake；
- 缓解：按编译错误逐个同步签名，保持未用方法 `UnimplementedError`，相关行为使用专用 fake。

- 版本名称采用可选字段；

- 批量删除后不重排版本号；
- 恢复使用复选框选择是否保存当前状态；
- 复选框默认未勾选；
- 管理入口采用顶栏“管理”；
- 同一笔记内名称不可重复；
- 名称最长50个字符。
