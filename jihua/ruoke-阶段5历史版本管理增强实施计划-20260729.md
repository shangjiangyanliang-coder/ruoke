# 历史版本管理增强 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为笔记历史版本提供自定义名称、管理模式下的批量永久删除，以及可选择是否保留当前完整状态的恢复流程；旧数据库升级后既有快照必须完整保留。

**Architecture:** 在既有 `note_version` 表上增加可空 `name` 字段，采用 Drift v1→v2 迁移。DAO 只负责查询与写入；Repository 在事务内处理所属笔记、名称和集合校验，并继续作为快照恢复的原子边界；Riverpod ViewModel 由纯列表状态改为版本管理状态；页面通过默认/管理两种模式呈现。

**Tech Stack:** Flutter、Dart、Riverpod、Drift、sqlite3、flutter_test、drift_dev。

## Global Constraints

- 仅在 `feature/notes-mvp` 分支开发；不 push、不重置 Git、不删除旧备份。
- 每个已存在文件首次改动前，先复制到 `beifen/`，命名为 `<原文件名>.backup-20260729-before-history-version-management`；同一文件本批只保留一份备份。
- 所有生产行为遵循 RED → GREEN → REFACTOR：先写能正确失败的定向测试，运行并确认失败原因，再写最小实现。
- `note_version.version_no` 永不重排；删除操作永久且必须二次确认。
- 自定义名称保存前 `trim()`；空值表示清除名称；最大 50 字符；同一 `noteId` 下不允许重复，跨笔记允许重复。
- 恢复默认 `saveCurrentBeforeRestore: false`；勾选时仅在当前完整快照与目标快照不同才新建一个版本。
- 不新增第三方依赖，不新增数据库唯一索引，不改变既有快照 JSON 格式。
- 每个生产 Dart 文件顶部保留或补充一行用途注释；复杂事务说明“为什么必须在同一事务中”。
