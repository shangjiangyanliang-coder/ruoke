# 阶段5第5批真机反馈改造设计

## 1. 背景与目标

阶段5第5批真机验证暴露两类问题：

1. 已有笔记的标签添加和移除会立即写入数据库，退出时选择“不保存”仍会保留标签变更。
2. `note_version.snapshot_json` 只保存正文 Delta，标题和标签变化不会形成完整历史版本。
3. 搜索范围弹窗一次展示全部书、章、节，数据增长后难以查找和选择。

本次改造目标：

- 标签与标题、正文采用一致的草稿和退出确认语义；
- 标题、正文、标签由同一 Drift 事务原子保存；
- 历史版本保存并恢复标题、正文、标签，兼容已有仅正文快照；
- 搜索范围改为按需加载的可搜索树，未搜索时只显示顶层书；
- 保留“全部笔记、仅书级、仅章级、仅节级”和指定节点子树语义；
- 不修改数据库表结构，不处理 F1.1.11、F1.1.12、F1.1.15，不 push。

## 2. 已确认交互

### 2.1 标签草稿

- 编辑器加载笔记时同时加载当前标签名称，作为本次会话的初始值。
- 添加和移除标签只修改编辑器内存状态，不立即创建标签或修改 `note_tag`。
- 标题、正文或标签任一变化，都视为未保存改动。
- 返回时统一提供“保存并离开 / 不保存离开 / 继续编辑”。
- “不保存离开”不产生任何标签写入；重新进入后仍显示数据库中的原标签。
- 点击保存时，新标签才按名称复用或创建，标签关联才被替换。

### 2.2 完整历史版本

- 新建笔记首次保存不创建历史版本。
- 已有笔记保存时，只要标题、正文或标签任一发生变化，就把保存前的完整状态写入历史。
- 新快照包含 `schemaVersion`、`title`、`contentJson`、`tagNames`。
- 标签按名称保存，不依赖可能被删除或变化的标签 ID。
- 恢复新格式版本时恢复标题、正文和标签；不存在的标签按名称重新创建。
- 恢复旧格式正文 Delta 时只恢复正文，保留当前标题和标签。
- 恢复前先保存当前完整状态，使恢复操作本身可以撤销。

新格式示例：

```json
{
  "schemaVersion": 1,
  "title": "笔记标题",
  "contentJson": "[{\"insert\":\"正文\\n\"}]",
  "tagNames": ["重点", "待复习"]
}
```

### 2.3 搜索范围树

- 全局范围使用紧凑入口，选项为“全部笔记、仅书级笔记、仅章级笔记、仅节级笔记”。
- 未输入关键词时只显示所有顶层书。
- 书可展开直接章，章可展开直接节；子节点按需读取并在弹窗会话内缓存。
- 展开按钮只展开或收起；点击名称才选择范围。
- 点击书选择书及全部后代，点击章选择章及其节，点击节只选择该节。
- 搜索按名称部分匹配书、章、节。
- 匹配章时显示所属书；匹配节时显示书和章，形成完整路径。
- 匹配到的书可展开章，匹配到的章可展开节。
- 清空关键词后回到顶层书列表。
- 关闭弹窗后搜索词、展开状态、缓存和错误全部销毁。

## 3. 架构方案

### 3.1 编辑器状态边界

`NoteEditorVm` 成为编辑会话的唯一草稿状态源，除当前 `Note` 外保存有序去重的 `tagNames`。界面通过 ViewModel 的 `addTagName`、`removeTagName` 修改草稿；标签建议仍读取全局标签目录，但不触发数据库写入。

保存时，ViewModel 把当前标题、正文和标签名称一次提交给 `NoteRepository`。保存成功后清除脏标记；保存失败时保留所有草稿状态。

### 3.2 Repository 聚合事务

扩展 `NoteRepository.create` 和 `NoteRepository.update`，增加可选 `tagNames` 参数。`LocalNoteRepository` 在单个 `_db.transaction` 中完成：

1. 读取旧笔记和旧标签；
2. 规范化、去重并比较新旧完整状态；
3. 有变化时写入旧完整快照；
4. 更新笔记及派生纯文本；
5. 重建重点标记；
6. 按名称复用或创建标签；
7. 替换 `note_tag` 关联。

事务中的所有异步数据库调用都必须 `await`，不得在事务闭包结束后继续使用事务上下文。任何步骤异常都由 Drift 回滚，并由 Repository 转换为现有 `DatabaseException`。

### 3.3 快照编解码

新增 `NoteEditSnapshot` 作为纯 Dart 模型，职责仅限：

- 规范化标签名称；
- 编码新格式对象 JSON；
- 识别并解析新格式；
- 将顶层 JSON 数组识别为旧正文 Delta；
- 为恢复流程提供 `isLegacy` 标记。

表字段仍使用现有 `snapshot_json TEXT`，因此数据库 schema 版本保持不变，不运行 Drift 代码生成。

### 3.4 科目查询与搜索路径

现有 `childrenOf(null)` 直接承担“只读取顶层书”，`childrenOf(id)` 承担展开节点。新增：

- `SubjectDao.searchByName(keyword)`：转义 LIKE 特殊字符并查询未软删除节点；
- `SubjectRepository.searchPaths(keyword)`：把匹配节点补齐为根到目标的 `SubjectPath`。

`SubjectPath.nodes` 始终按书、章、节顺序排列。最大深度固定为 3，Repository 最多向上读取两次父节点，不需要全量加载科目树。

### 3.5 范围选择状态

新增自动销毁的 `SubjectScopePickerVm`，每次弹窗使用独立会话键。状态包含：

- 顶层书；
- 搜索路径；
- 已展开节点；
- 已加载子节点缓存；
- 根加载、搜索、单节点展开错误；
- 当前搜索请求代次。

关键词输入使用约 250ms 防抖。旧请求即使后返回，也不能覆盖新关键词结果。关闭弹窗时取消 Timer 并销毁状态。

## 4. 数据流

### 4.1 保存

```text
编辑器输入
  -> NoteEditorVm 草稿
  -> 点击保存
  -> NoteRepository.update(..., tagNames)
  -> Drift 单事务：旧快照 + note + highlight + tag + note_tag
  -> 成功：清除 dirty
  -> 失败：回滚数据库并保留草稿
```

### 4.2 恢复

```text
选择历史版本
  -> 解析 snapshot_json
  -> 读取当前完整状态
  -> 保存当前完整快照
  -> 新格式：恢复标题 + 正文 + 标签
     旧格式：恢复正文，保留当前标题 + 标签
  -> 重建纯文本、重点标记、标签关联
```

### 4.3 范围选择

```text
打开弹窗
  -> childrenOf(null) 只加载书
  -> 展开书/章时 childrenOf(id)

输入关键词
  -> 250ms 防抖
  -> searchPaths(keyword)
  -> 显示匹配节点及祖先路径
  -> 展开匹配书/章时按需加载其子节点
```

## 5. 错误与边界

- 空标签名称不进入草稿；同名标签在草稿内去重。
- 标签添加后再移除可保留粗粒度 dirty 提示，但不写数据库。
- 新建笔记仅有标签、没有标题和可见正文时仍按空笔记处理，不创建笔记和标签。
- 保存失败不离开编辑器、不清空草稿。
- 旧快照损坏时恢复返回失败，不覆盖当前笔记。
- 新快照中的标签已被删除时恢复会重新创建；同名标签存在时复用。
- 搜索 `%`、`_`、反斜杠时按普通字符处理。
- 根书加载失败显示整页重试；搜索失败保留关键词；子节点失败只影响对应分支。
- 选择后节点被删除仍由现有搜索 Repository 校验并提示重新选择。

## 6. 测试策略

严格执行 RED → GREEN → REFACTOR：

1. 快照单元测试：新格式往返、标签规范化、旧 Delta 兼容、损坏数据失败。
2. Repository 内存数据库测试：标签只改产生版本、完整恢复、旧版恢复、事务回滚。
3. ViewModel 测试：标签只改进入 dirty、失败保留、成功清除。
4. 编辑器 Widget 测试：添加/移除不即时写库、三种退出选择、标签-only 保存。
5. 科目 Repository 测试：根节点、子节点、路径补齐、LIKE 字面量。
6. 范围选择 ViewModel 测试：缓存、防抖、旧请求隔离、分支错误。
7. 范围选择 Widget 测试：默认只显示书、逐级展开、搜索上下文、选择语义、会话重置。
8. 全量执行 `flutter analyze --no-pub`、`flutter test --no-pub`、`flutter build apk --debug --no-pub`。

真机验证由用户执行，重点复测退出不保存、标签-only 历史版本、旧版本恢复、树形展开和书章节名称搜索。
