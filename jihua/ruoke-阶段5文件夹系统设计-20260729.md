# 阶段5文件夹系统设计

**日期：** 2026-07-29  
**状态：** 已确认，待编写实施计划  
**关联需求：** F1.1.15「书向上加文件夹」

## 1. 目标与范围

为书、章、节结构增加独立、可无限嵌套的文件夹系统，用于归纳大量书籍并使笔记界面保持简洁。

已确认的交互规则：

- 文件夹可无限嵌套，类似 Windows 文件夹；
- 文件夹只容纳子文件夹和书，笔记只能归属书、章、节；
- 文件夹可作为通用搜索和标签搜索的范围，递归包含后代文件夹、书、章、节的笔记；
- 允许书未归入文件夹；升级后的已有书保持未分组；
- 删除非空文件夹采用“解散”语义：子文件夹和书移动到上一级，不删除书或笔记；
- 笔记主界面和管理界面均采用逐级进入，而不是同页无限展开；
- 书、章、节也采用逐级进入的统一浏览方式。

本批不实现拖拽排序、文件夹回收站、文件夹内直接挂笔记、书在多个文件夹重复出现或云同步。

## 2. 方案选择

### 2.1 候选方案

1. 将现有 `subjects.level` 整体后移：文件夹=0、书=1、章=2、节=3；
2. 新增独立文件夹表，书保留 `level=0`，仅在书上保存可空 `folderId`；
3. 仅为书保存普通文本分组名，作为虚拟书架。

### 2.2 最终方案

采用方案 2：独立文件夹表 + 书的可空文件夹归属。

### 2.3 选择理由

现有笔记、搜索范围、科目路径、图标和管理页都将 0/1/2 固定解释为书/章/节。整体后移会改变已有数据语义并扩大回归范围。独立表可保留全部已有 subject ID、level、parentId 和 note.subjectId，仅新增组织关系，迁移风险最低。

## 3. 数据模型与迁移

### 3.1 新表 `subject_folders`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT | UUID 主键 |
| `parent_id` | TEXT nullable | 上级文件夹，null 表示根文件夹 |
| `name` | TEXT | 文件夹名称 |
| `sort_order` | INTEGER | 同级排序 |
| `created_at` | INTEGER | 创建时间毫秒 |
| `updated_at` | INTEGER | 更新时间毫秒 |
| `is_deleted` | BOOLEAN | 软删标志 |
| `deleted_at` | INTEGER nullable | 软删时间 |

### 3.2 `subjects` 扩展

新增可空字段 `folder_id`。

- 仅 `level=0` 的书可写入；
- 章和节必须保持 `folderId=null`；
- `folderId=null` 表示未分组书籍；
- 每本书至多属于一个文件夹。

### 3.3 升级策略

数据库 schema 由 v2 升级至 v3：

1. 创建 `subject_folders`；
2. 向 `subjects` 增加可空 `folder_id`；
3. 不修改已有 subject、note、tag、highlight、version 数据；
4. 已有书默认 `folderId=null`，显示在“未分组书籍”；
5. 不自动创建默认文件夹，不自动移动用户数据。

不在数据库列上依赖外键级联；Repository 在事务边界验证文件夹、书和父子关系，避免 SQLite 迁移兼容风险。

## 4. 领域接口与事务规则

新增 `SubjectFolder` 模型和 `FolderRepository`，与既有 `SubjectRepository` 分离。

核心能力：

```dart
Future<Result<List<SubjectFolder>>> childrenOf(String? parentId);
Future<Result<List<Subject>>> booksIn(String? folderId);
Future<Result<String>> create({required String name, String? parentId});
Future<Result<void>> rename({required String id, required String name});
Future<Result<void>> moveFolder({
  required String folderId,
  required String? newParentId,
});
Future<Result<void>> moveBook({
  required String bookId,
  required String? folderId,
});
Future<Result<void>> dissolve(String folderId);
```

Repository 校验：

- 名称 trim 后不能为空，最长 50 字符；
- 同一父文件夹下文件夹名唯一；
- 不能将文件夹移动到自身或任意后代；
- `moveBook` 只接受仍有效的书级 subject；
- 父文件夹、目标文件夹、书不存在或被软删时返回可读校验错误；
- 文件夹重命名、移动、解散均不能留下部分更新。

`dissolve(folderId)` 在同一个数据库事务中执行：读取目标文件夹和其上级 → 将直接子文件夹父级改为上级 → 将直接书的 folderId 改为上级 → 软删目标文件夹。根文件夹被解散时，书转为未分组，子文件夹转为根文件夹。

## 5. 浏览与管理交互

### 5.1 逐级浏览

```text
根目录
├─ 根文件夹
├─ 未分组书籍
└─ 未分类笔记

文件夹 → 子文件夹、书
书     → 直属笔记、章
章     → 直属笔记、节
节     → 直属笔记
```

每页仅显示当前容器直属内容，顶部显示可返回路径。路径过长时横向滚动，不采用无限缩进。

容器行显示名称、直属子项数量和笔记数量；点击进入下一层。笔记行保持现有编辑与删除入口。编辑器返回后仅刷新当前路径页。

### 5.2 新建笔记

- 位于书、章、节页：FAB 默认在当前 subject 新建；
- 位于根目录、文件夹页：FAB 打开逐级定级选择器；
- 文件夹仅用于进入，不能作为笔记目标；
- 逐级定级选择器可搜索路径，并显式确认书、章或节。

### 5.3 文件夹与科目管理

管理页同样采用逐级进入：

- 根目录：新建根文件夹、新建未分组书；
- 文件夹：新建子文件夹、在当前文件夹新建书、重命名、移动、解散；
- 书：移动到文件夹，保留既有书/章/节管理能力；
- 移动目标采用可搜索的逐级文件夹选择器，不实现拖拽；
- 解散确认弹窗展示将被迁移的直接子文件夹和书数量、目标位置，并强调不删除笔记。

### 5.4 搜索范围

新增 `SubjectScope.folder(folderId)`，并新增“未分组书籍”虚拟范围。

文件夹范围解析：递归收集目标文件夹和全部后代文件夹 → 收集其下书籍 → 使用既有 subject 后代解析获取书、章、节 ID → 查询笔记。

保留既有范围语义：

- 全部书/章/节只匹配直接归属于对应 level 的笔记；
- 指定书、章、节匹配自身及后代；
- 指定文件夹匹配其所有后代文件夹内全部书、章、节笔记。

范围选择器可搜索文件夹、书、章、节名称，并显示完整路径。文件夹、未分组书籍、书、章、节都可选择搜索范围。

## 6. 状态与组件边界

避免一个巨型页面或 ViewModel，拆分为：

| 组件 | 职责 |
|---|---|
| `LibraryBrowserView/Vm` | 根、文件夹、书、章、节逐级浏览和笔记列表 |
| `LibraryManageView/Vm` | 文件夹创建、移动、重命名、解散和书籍移动 |
| `LibraryLocationPicker/Vm` | 新建笔记的逐级位置选择 |
| `LibraryScopePicker/Vm` | 通用搜索、标签搜索的逐级范围选择 |
| 共享模型与小组件 | 路径、容器行、文件夹搜索结果、计数展示 |

浏览位置采用显式 `LibraryLocation`（根、文件夹、未分组、subject），路由支持返回与路径恢复。文件夹和 subject 的展开/导航状态使用不同 ID 集合或不同位置类型，避免同名或标识混淆。

## 7. 错误与兼容处理

- 浏览中的文件夹被删除：提示并返回父级；父级不存在则回根目录；
- 循环或孤立文件夹：不递归崩溃，放入“需要整理”分组；
- 指向失效 folderId 的书：显示在未分组书籍；
- 已失效的搜索范围：清除范围并提示重新选择；
- 文件夹写入成功、页面刷新失败：保留写入成功语义，单独提示刷新失败；
- 文件夹不纳入笔记历史版本快照，移动书或文件夹不修改笔记正文、标签、重点和历史版本。
