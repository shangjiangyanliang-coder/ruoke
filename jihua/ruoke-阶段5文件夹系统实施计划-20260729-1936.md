# 阶段 5：多级文件夹系统实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` after the user confirms this plan. Execute the tasks in order, using TDD: write a failing test, implement the smallest change, then run the listed targeted test before proceeding.

**目标：** 在现有“书 → 章 → 节”体系之上增加可无限嵌套的独立文件夹；将笔记浏览、笔记创建定位、标签搜索范围和层级管理统一为逐级进入的交互，同时保持现有书、章、节、笔记、标签、重点标记和历史版本数据兼容。

**总体架构：** 文件夹独立于 `subjects.level`。数据库新增 `subject_folders`，书（仅 `level == 0`）以可空 `folder_id` 归属文件夹；章、节不保存文件夹归属。界面以明确的 `LibraryLocation` 表示根目录、文件夹、未归类书或书/章/节，不再以一棵无限缩进的树呈现所有内容。

**技术栈：** Flutter、Riverpod、Drift/SQLite、GoRouter、既有 Result 错误模型与 Flutter 单元/组件测试。

## 全局约束

- 数据库由 v2 升级至 v3；已有书保持 `folder_id = NULL`，不迁移或删除任何现存笔记及关联数据。
- 文件夹可无限嵌套，但禁止移动到自身或后代；文件夹名只要求同一父目录下唯一，名称会先 `trim`，不能为空且最长 50 字。
- 删除文件夹采用“安全解散”：直属子文件夹和直属书移至其父目录；根文件夹解散后直属书改为未归类书。不会删除书、章、节、笔记、标签、重点标记或历史版本。
- 书可不放入文件夹；章、节仍只通过 `parent_id` 隶属书或章，不能直接放入文件夹。
- 文件夹范围搜索包含该文件夹全部后代文件夹中的书，以及这些书下的章、节笔记；“未归类书”范围包含所有 `folder_id = NULL` 书及其后代章、节。
- 不引入拖拽排序；移动使用可搜索、逐级选择的定位器，避免书多后出现长列表。
- 此批不处理既有 F1.1.10～F1.1.15 中与文件夹无关的遗留问题，不顺带重构笔记编辑器、标签或历史版本功能。
- 在修改任何既有文件前，按项目规则先复制到 `beifen`；本计划中新建的文件不需要备份。测试产生的临时文件只放 `ceshi`，完成后标记是否可删除。
- 不推送远程仓库；每一批本地提交只包含该批文件，不能夹带当前工作区中已有的 `lujing.md`、`pubspec.yaml` 改动。
